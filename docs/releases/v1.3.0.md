# TransDot v1.3.0

- Android 输入栏直接提供图库和文件入口，保留多选与原有上传流程。
- Android 和 Web 统一为月亮、显示器、太阳三段式主题切换，支持深色、跟随系统、浅色及本机偏好保存。
- 双端支持修改已有纯文本，保留创建时间，标记“已编辑”，同步全文搜索和实时事件；并发修改通过 revision 检测冲突。
- 双端支持跨分组选择文字、图片和文件并删除。“全选”只包含已加载消息，部分失败可重试。
- 网页标签名改为 `T-dot传输助手`。
- 新授权浏览器默认只能访问授权之后的消息，可申请 APP 开放全部历史；APP 可以批准、拒绝和撤销。升级前已有浏览器保留历史访问权限。
- Android 增加 APP 内在线更新：GitHub 正式版本检查、系统后台下载、大小/SHA-256/包名/版本/签名校验及系统安装入口。

## 升级

先备份数据，再升级服务端与 Web，最后安装 APP。数据库自动升级至 schema 12；使用新版备份与恢复脚本。不要用旧镜像直接打开已迁移的数据库，回退时恢复升级前备份。

APP 版本号 `1.3.0`，versionCode `11`。正式发布的 APK 必须沿用原签名证书，才能保留原配对和设置进行覆盖升级。

旧 APP 没有在线更新入口，因此首次升级至本版本需要安装一次 APK；后续版本可以在 APP 内完成下载并发起安装。首次安装来源授权及系统安装确认仍由用户操作。

更新仅针对 APP，不会自动升级 Docker 服务端。新版编辑和历史审批需要服务端支持；旧客户端不会展示编辑标记或审批界面，应一并更新。

## 发布附件

每次正式 GitHub Release 上传以下文件，`update.json` 必须和 APK 放在同一个版本：

- `TransDot-v1.3.0-arm64-v8a.apk`
- `TransDot-v1.3.0-universal.apk`
- 两个同名 `.sha256` 文件
- `update.json`

签名并验证两个 APK 后，在仓库根目录执行：

```powershell
$env:ANDROID_HOME='你的 Android SDK 目录'
$env:JAVA_HOME='你的 JDK 目录'
node android/scripts/create-update-manifest.mjs --arm64 artifacts/release-v1.3.0/TransDot-v1.3.0-arm64-v8a.apk --universal artifacts/release-v1.3.0/TransDot-v1.3.0-universal.apk --notes docs/releases/v1.3.0.md --output artifacts/release-v1.3.0/update.json
```

脚本会验证正式包名、版本、最低 Android 版本、ABI 和 APK 签名，要求各架构包版本及签名一致，再生成大小、SHA-256 和更新地址。只发布经过正式签名的 APK，签名文件及凭据不得上传。

APP 每 24 小时最多自动检查一次，设置页可手动检查。未连接服务器时，连接页底部也有检查入口；下载可在后台继续，返回后可继续安装。调试包不自动检查正式版更新，不能覆盖安装正式包。

## 验证

自动测试覆盖消息编辑、搜索索引、冲突、历史权限及 REST/实时事件访问限制、更新清单选择及校验规则。Web、Go 和 Android 自动化检查通过，正式 APK 已完成签名与 ABI 验证，用户手机端验收通过。

服务端和 Web 已部署至 v1.3.0，生产数据库升级至 schema 12，消息、文件及设备记录数量保持一致，健康检查和数据库完整性检查通过。
