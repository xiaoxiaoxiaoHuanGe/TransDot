# TransDot v1.1.0 Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan with verification checkpoints.

**Goal:** Publish the accepted feature set as a signed `v1.1.0` release and leave only the latest local `main` checkout.

**Architecture:** Documentation and version metadata are committed on `codex/d`, then `main` is fast-forwarded to that commit. The release APK is built unsigned by Gradle, aligned and signed outside the repository with the private PKCS12 material, verified, and uploaded with a checksum.

**Tech Stack:** Git, GitHub CLI/API, Gradle, Android SDK `zipalign`/`apksigner`, Go, React/Vite, Docker Compose.

## Global Constraints

- No business-logic changes.
- Android release is `versionName=1.1.0`, `versionCode=8`, tag `v1.1.0`.
- Signing secrets never enter Git or command output.
- Remote and local C/D branches are removed only after the release is remotely verified.

### Task 1: Release documentation and metadata

- [ ] Rewrite `README.md` around current user and operator workflows.
- [ ] Update Android version metadata and `.env.example` wording.
- [ ] Review the diff and commit the release preparation.

### Task 2: Verification and signed artifact

- [ ] Run complete Go, Web, and Android tests/builds.
- [ ] Build the unsigned release APK.
- [ ] Align, sign, verify, and hash `TransDot-v1.1.0.apk` without exposing credentials.

### Task 3: Merge and publish

- [ ] Fast-forward local `main` to `codex/d` and rerun release checks.
- [ ] Push `main`, create and push signed tag `v1.1.0`.
- [ ] Create the GitHub Release and upload the signed APK and checksum.

### Task 4: Cleanup

- [ ] Verify remote main, tag, release assets, and local main state.
- [ ] Remove remote `codex/c` and `codex/d`.
- [ ] Remove the D worktree and local C/D branches; leave `D:\TransDot` on clean `main`.
