# TransDot 配对保护与服务器标识设计

## 背景

多服务器测试暴露了两个体验问题：Web 通过局域网明文 HTTP 地址访问时，浏览器拒绝发送服务端设置的 `Secure` 配对 Cookie，随后用户连续重试会耗尽两分钟的配对创建限额；同时 APP 与 Web 的顶栏缺少足够醒目的服务器标识，用户容易把内容发送到错误的服务器。

本轮在不降低认证安全性、不建立后台多服务器连接的前提下，修复配对错误反馈并强化当前服务器辨识。

## 目标

1. Web 在无法安全保存配对 Cookie 的地址上，不创建配对会话，并给出可执行的中文提示。
2. 配对创建被限流时，服务端返回准确等待时间，Web 显示倒计时并阻止重复提交。
3. APP 顶栏始终显示当前服务器档案名称及当前连接状态。
4. APP 设置页同时显示档案名称、地址和状态，但只连接及探测当前档案。
5. APP 切换成功后显示明确反馈。
6. Web 顶栏显示当前主机和端口，便于区分不同 Docker 实例。

## 非目标

- 不允许通过配置关闭 `Secure` Cookie。
- 不为局域网 IP 签发或安装本地 TLS 证书。
- 不后台连接或轮询所有服务器档案。
- 不修改服务器数据库结构。
- 不改变现有配对码、二维码或浏览器替换规则。

## 方案选择

采用“前端预检 + 服务端准确限流元数据 + 当前档案单连接状态”的组合方案。

未采用允许不安全 Cookie 的开发开关，因为开关可能被误带到公开部署。未采用自动配置本地 HTTPS，因为证书信任与域名解析显著增加 Docker Desktop 测试复杂度。未采用后台探测所有服务器，因为它与只连接当前档案的既定约束冲突，并会增加耗电和错误噪声。

## Web 配对保护

### 安全地址判定

新增纯函数判定当前页面是否可以发起配对：

- `https:` 始终允许。
- `http:` 仅允许 `localhost`、`127.0.0.1` 和 `::1`。
- 其他 `http:` 主机在首次认证检查返回 401 后，直接进入专用错误状态，不调用 `POST /api/v1/pairing/sessions`。

错误文案明确说明：当前地址无法保存安全配对凭据；同一台电脑请使用 `http://localhost:<端口>`，其他设备请配置 HTTPS。页面不提供会再次创建会话的普通重试按钮，只允许用户修改地址后刷新。

### 限流响应

现有固定窗口限流器增加一个返回结果，包含：

- 是否允许本次请求。
- 若拒绝，距离当前窗口结束还需等待的秒数，向上取整且至少为 1。

`POST /api/v1/pairing/sessions` 返回 429 时设置标准 `Retry-After` 响应头，并保留现有 `RATE_LIMITED` 错误码。其他限流端点继续使用现有行为，本轮不扩大接口改动范围。

### Web 倒计时与并发保护

请求封装读取 `Retry-After` 并写入 `ApiError.retryAfterSeconds`。配对页面收到 429 后：

- 显示“请求过于频繁，请在 N 秒后重试”。
- 重试按钮显示剩余秒数并保持禁用。
- 倒计时归零后恢复按钮。
- `createSession` 使用同步互斥引用，阻止 React 状态提交前的快速重复调用。
- 页面卸载或新请求开始时清理旧倒计时状态。

## 服务器标识

### APP 顶栏

从 `serverProfiles` 与 `activeProfileId` 派生当前 `ServerProfileSummary`，将名称传入时间线顶栏。顶栏第一行显示“传输助手 · <档案名称>”，第二行保留连接状态。名称过长时单行省略，操作按钮仍可用。

### APP 设置页

每个服务器卡片继续显示档案名称和完整地址，并新增状态标签：

- 当前档案根据时间线连接状态显示“已连接”“连接中”或“离线”。
- 非当前档案显示“已保存”，不暗示后台在线状态。

切换成功后，新时间线显示一次“已切换到 <档案名称>”提示。该提示状态放在 `sessionGeneration` 之外，由 `MainActivity` 在切换完成时写入并由新建的 `TimelineScreen` 消费，避免重建界面时丢失。

### Web 顶栏

从 `window.location.host` 生成只读实例标签，在配对页和时间线顶栏显示，例如 `localhost:5758` 或 `file.example.com`。标签不参与认证，也不请求新接口；窄屏时允许省略显示。

## 错误处理

- 无法安全配对与请求限流使用不同状态和文案。
- 非数字或缺失的 `Retry-After` 使用前端保守默认值 120 秒。
- 服务器切换失败时不显示成功提示，并保留当前档案。
- 当前档案无法从列表派生时，顶栏退化为“服务器”，避免崩溃。
- 不把非当前档案标记为离线，因为系统没有连接或探测它们。

## 测试设计

### Go

- 固定窗口达到上限时返回准确剩余时长。
- 窗口到期后允许请求并重置计数。
- 配对创建 429 包含整数 `Retry-After`。

### Web

- HTTPS、localhost、127.0.0.1、::1 被允许配对。
- 局域网 HTTP 地址被阻止并生成正确引导文案。
- `Retry-After` 的有效值、缺失值和非法值正确归一化。
- 倒计时按钮在等待期间禁用，归零后恢复。
- 实例标签保留主机和非标准端口。

### Android

- 能从档案列表派生活动服务器名称。
- 当前档案根据连接状态生成正确标签，非当前档案始终为“已保存”。
- 切换失败不产生成功反馈；切换成功反馈包含目标档案名称。

## 验收标准

1. 使用 `http://192.168.x.x:<端口>` 打开未配对 Web 时，不产生配对创建请求，并显示 HTTPS/localhost 指引。
2. 达到配对创建限制后，响应包含 `Retry-After`，Web 倒计时期间无法再次提交。
3. 使用 `http://localhost:5758` 可以正常生成配对码并完成配对。
4. APP 在 5757 与 5758 间切换时，顶栏名称随档案变化，切换成功提示准确出现。
5. 设置页只把当前服务器显示为实时连接状态，其他服务器显示“已保存”。
6. Web 5757 与 5758 顶栏分别显示对应端口。
7. Go、Web、Android 自动化测试和构建全部通过。
