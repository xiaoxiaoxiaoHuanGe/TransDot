# TransDot v1.1.0 Release Design

## Scope

- Publish the accepted LAN transfer and secure phone rebind work as `v1.1.0`.
- Set Android `versionName` to `1.1.0` and `versionCode` to `8` without changing runtime behavior.
- Replace the outdated README with a concise operational guide covering deployment, binding, rebind, LAN transfer, configuration, updates, reset, backup, and builds.
- Build a release APK, sign it with the user-provided PKCS12 key, verify the signature, and publish it with a SHA-256 checksum.
- Fast-forward `main` to the accepted feature history, publish the tag and release, then remove local and remote `codex/c` and `codex/d` branches.

## Safety

- Do not expose signing credentials in files, logs, commits, or shell output.
- Do not delete branches or worktrees until `main`, the tag, and the GitHub Release have been verified remotely.
- Preserve the persistent Docker volume during normal updates; document reset as an explicitly destructive recovery action.

## Release Notes

The release description will highlight Web-to-Android QR rebind, immediate old-phone credential revocation, direct LAN file transfer, Android multi-file queues and automatic receive folders, the three-line Android header, and deployment/update improvements.
