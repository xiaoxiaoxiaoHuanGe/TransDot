# TransDot Desktop v2 — Windows 轻量版

新建在独立分支的 Tauri 2 / WebView2 桌面客户端。它不替换现有 desktop/ Electron 版本。
原 Android、Go 服务器、React 网页及配对 API 均不改动，服务器无需升级。

## 功能

- 使用已有服务器页面和 APP 配对机制，保留原时间线。
- 新的 Android 文字消息自动写入 Windows 系统文本剪贴板。
- 新的 Android 图片消息自动下载、解码成原尺寸 PNG，然后写入 Windows 图片剪贴板。
- Windows 关闭窗口继续驻留系统托盘。托盘菜单集中提供打开面板、自动复制开关、开机启动、更换服务器、快捷键设置和完全退出。
- 默认全局快捷键为 Ctrl+Shift+T，可在“快捷键设置”中录制并保存自定义组合键；设置保存在本地，重启后继续生效。
- 登录状态留在 Windows WebView2 的浏览器配置中，不复制主账号 Token 到本地配置文件。
- 不复制历史消息，避免重连后覆盖剪贴板；被服务器撤销授权后停止接收。
- 网络中断期间消息仍留存在时间线上，不保证离线消息补复制。
- 设计蓝白独立应用图标（手机 ↔ 屏幕 + TransDot dot）。

## 构建

需 Windows 11 或装有 WebView2 的 Windows 10，Node.js 22、Rust stable >=1.90 和 Microsoft C++ Build Tools。

在 desktop-v2 运行：

    npm install
    npm run icons
    npm test
    npm run build

安装版输出路径为 src-tauri/target/release/bundle/nsis/。
GitHub Actions 工作流 TransDot Windows Tauri v2 自动生成构建产物并展示 EXE 实测大小。

## 安全边界

- 远程服务器必须使用 HTTPS（本机 localhost / 127.0.0.1 允许 HTTP 调试）。
- 配置文件仅保存服务器地址和剪贴板自动复制开关，保存在 Tauri 应用配置目录。
- Rust 主进程仅允许标签为 remote 且 URL origin 与已配置服务器完全一致的窗口进行剪贴板写入。
- 限制 WebView 页面导航到设置的服务器 origin。
- 远程页面使用受限制的 Tauri 命令；为支持用户自定义服务器域名，当前 capability 对 HTTPS 域名采用广泛 URL 匹配，但所有敏感命令在 Rust 侧再次强校验实际窗口来源。发布前仍建议安全审计。
- 原始图片下载最多 12 MiB，最大 1200 万像素，解码后的 PNG Base64 最多 16 MiB。
- WebView2 runtime 通过系统提供；安装器默认在缺少运行环境时下载引导安装包，离线机器需要额外安装 WebView2。

## 验收清单

1. 新安装后填服务器地址；Android 扫码授权。
2. APP 发送普通文字，在 Windows 记事本 Ctrl+V 确认。
3. APP 发送 PNG/JPEG，在 Windows 画图 Ctrl+V 确认实际图片内容。
4. 关闭主窗口之后复测两种剪贴板写入。
5. 托盘“暂停/启用”切换后确认行为。
6. 启用开机启动、注销/登录后验证后台接收。
7. 在 GitHub Actions 日志内核验 Windows 安装包真实大小，与 Electron 的单文件 EXE 对比。

### 已知风险

桌面端要加载部署在服务端的 Web 页面，必须保证现有反向代理正常支持 WebSocket。
Windows WebView2、真实剪贴板接入和实际运行需要 Windows 电脑做人工验收；CI 编译及单元测试通过并不等于所有运行场景通过。

## v2.0.1 剪贴板诊断

- 在系统托盘右键 TransDot，选择“测试写入 Windows 剪贴板”，然后打开记事本按 Ctrl+V：应出现“TransDot v2.0.1：Windows 系统剪贴板写入测试成功。”
- 如果本机测试成功，再从 Android 发送一条全新的文字。在记事本 Ctrl+V；如果不能粘贴，请在系统托盘选择“复制接收器诊断信息”，将诊断文本粘贴给维护者。
- 诊断不会记录消息正文、图片内容、Cookie、密钥或配对 Token。只记录连接与剪贴板操作的状态。
- 默认 HTTPS 443 和非标准 HTTPS 端口（例如 9004）都可以使用；Rust 仍然校验实际服务器 origin，其他来源不得写入剪贴板。
- 安装程序支持简体中文与 English，在开始安装时选择。默认按照 Windows 系统语言匹配，未匹配时回退到列表第一项（简体中文）。
- 升级安装前建议在系统托盘完全退出旧版。v2.0.1 不改变与服务器、Android 的协议。

## v2.0.2 后台自动复制可靠性修复

- 服务器页面加载完成后，Tauri 再次尝试初始化接收器（配合页面开始时注入）。
- 对已绑定且授权的设备，额外每 4 秒校验一次最新消息，以弥补 WebSocket 消息丢失；首次成功校验仅建立历史基线，不覆盖当前剪贴板。
- 托盘固定展示不可点击的 **自动复制状态：已启用/已暂停**，并提供与状态对应的唯一动作 **暂停自动复制/启用自动复制**。切换即时更新，重新启动后从本地设置恢复状态。
- 系统托盘“复制接收器诊断信息”可以判断网页是否已经加载、实时通道是否连接、REST 校验是否已开启、新消息是否触发复制。
- 如果仍未能收到 Android 消息，请在发送一条新文字后，把托盘诊断文本粘贴给维护者；不会包含消息正文或授权 Cookie。

### 排查建议（按顺序）
1. 右键托盘选择 **测试写入 Windows 剪贴板**。在记事本 Ctrl+V 验证原生写入。
2. 右键托盘选择 **测试消息接收链路**。再次 Ctrl+V 验证 WebView → 原生命令链路；这一项必须显示“桌面消息接收链路测试成功”。
3. Android 发送新的文字。若仍不能复制，再选择 **复制接收器诊断信息** 并提供状态内容，便于区分“桥接未启动 / 设备未授权 / WebSocket 未连接 / REST 校验失败 / 原生权限失败”。

## v2.0.4 托盘菜单与全局快捷键

- 精简右键菜单，移除面向维护人员的诊断入口；常用操作保留在主菜单。
- 自动复制与开机启动改为带勾选状态的菜单项。
- 新增可自定义全局快捷键，默认 Ctrl+Shift+T，用于快速打开 TransDot 面板。
- 设置窗口支持录制、保存、冲突提示和恢复默认；旧配置文件会自动补齐默认快捷键，不会丢失服务器地址或自动复制状态。

## v2.0.3 原因及修复

Tauri 2.11+ 对远程网页调用自定义 Rust 命令新增严格 ACL 校验。此前只有 remote URL + core:default，Windows 本机测试不会触发该校验，导致远程网页收到 Android 消息也不能调用 copy_text 或 copy_image_png。

使用 AppManifest 在构建时注册六个应用命令，并将复制相关权限只授予远程窗口、配置命令只授予本地设置窗口。仍由 Rust verify_remote 检查完整服务器来源和暂停状态。保留原生和网页两级测试入口。

如果这版安装后链路测试仍失败，先在托盘复制接收器诊断信息；暂时使用已验证的 Electron 桌面版，不应反复更新生产程序。
